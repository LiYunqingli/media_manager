# 06 · 播放器说明

对应需求 6：「播放器需要功能完善，长按倍速（松开正常），左右滚动拉进度，
左右上下（左亮度右音量）。」

以及对需求 5 的落地：收藏、记录上次观看位置、观看次数（超过 10 秒才算一次）。

## 1. 为什么自研播放器

HTML5 `<video>` 只提供播放内核，原生 `controls` 既不能改样式，也无法实现
「长按倍速」「左右分屏手势」这类交互。第三方播放器（如 video.js）体积大、
定制成本高，且本项目已经全量本地化前端依赖，再引一个大库不划算。

结论：**只保留 `<video>` 内核（`controls` 关闭），自己写一层控件**。
实现集中在 `frontend/static/js/player.js`，单文件 900 行左右，零依赖，
只依赖 `MM.util`、`MM.config`、`MM.ui` 三个已有模块。

## 2. 初始化方式

一个容器 div + 一个 options 对象即可：

```html
<div id="player"></div>

<script>
  var mp = new MM.Player('#player', {
    src: '/media/videos/2025/09/xxxx.mp4',   // 播放地址（来自 /play-info）
    poster: '/media/covers/2025/09/xxxx.jpg',
    title: '视频标题',
    lastPosition: 128.5,                     // 续播位置（秒），来自 /play-info
    autoplay: true,
    onReport: function (payload) {           // 心跳上报回调
      MM.http.post('/api/client/videos/12/play-report', {
        segment_id: segmentId,               // 本次播放会话 uuid
        position: payload.position,
        duration: payload.duration,
        delta: payload.delta
      });
    },
    onEnded: function () { /* 自动连播 ... */ }
  });
</script>
```

`options` 全字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `src` | string | 视频地址 |
| `poster` | string | 封面 |
| `title` | string | 视频标题（写入 `<video title>`） |
| `lastPosition` | number | 续播起点（秒） |
| `autoplay` | bool | 元数据加载后自动播放（可能被浏览器拦截，属正常） |
| `reportInterval` | number | 心跳间隔覆盖（秒），默认取 `MM.config.PLAY_REPORT.INTERVAL` |
| `onReady` | fn(self) | `loadedmetadata` 后触发 |
| `onPlay` / `onPause` / `onEnded` | fn() | 对应视频事件 |
| `onError` | fn(err) | 视频错误 |
| `onReport` | fn(payload) | 心跳/离开页面时的进度上报回调 |

## 3. 功能总览

### 3.1 基础控件

- 播放 / 暂停（居中大按钮 + 控制栏按钮 + 点击画面）
- 进度条：已播进度、缓冲进度（`buffered`）、拖动预览气泡（显示目标时间）
- 时间显示：当前 / 总时长
- 音量：滑块 + 静音按钮（图标随音量在 🔊 / 🔉 / 🔇 间切换）
- 倍速菜单：0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 2.0 / 3.0，可扩展
- 全屏、网页全屏、加载态、封面

### 3.2 播放器手势（移动端 `isTouch` 时启用）

| 手势 | 行为 | 实现要点 |
| --- | --- | --- |
| 长按 450ms | 倍速 3x 播放，松开恢复用户倍速 | `_beginLongPress` / `_endLongPress` |
| 水平滑动 | 拖动进度（跟手预览目标时间） | 滑动距离按容器宽度映射到时长 |
| 左半屏上下滑 | 亮度（黑遮罩模拟） | 浏览器改不了系统亮度，用 `.mp__dim` 的 `opacity` 模拟 |
| 右半屏上下滑 | 音量 | 滑动距离按容器高度 90% 映射 0~1 |
| 单击 | 显隐控制栏 | 260ms 内判定为「单击」 |
| 双击（260ms 内） | 播放 / 暂停 | `_lastTapAt` 时间戳比对 |

方向判定：触摸移动超过 8px 阈值后，按 `|dx| > |dy|` 决定是 `seek`，
否则按起手位置落在左半屏还是右半屏决定 `brightness` / `volume`。
判定后锁定 `g.mode`，本次滑动不再改变模式。

### 3.3 播放器手势（桌面端）

| 交互 | 行为 |
| --- | --- |
| 单击 | 播放 / 暂停 |
| 长按 450ms | 倍速 3x，松开恢复 |
| 滚轮 | 音量 ±5% |
| 进度条拖动 | seek |
| 鼠标移入控制栏 | 保持控制栏常显 |

### 3.4 键盘快捷键

| 按键 | 行为 |
| --- | --- |
| `空格` / `K` | 播放 / 暂停 |
| `←` / `→` | 快退 / 快进 10 秒（按住 `Shift` 为 30 秒） |
| `↑` / `↓` | 音量 +5% / −5% |
| `M` | 静音切换 |
| `F` | 全屏 |
| `W` | 网页全屏 |
| `[` / `]` | 倍速 −0.25 / +0.25 |
| `0`-`9` | 跳转到 0%~90% |

键盘事件绑定在 `document` 上，但会跳过 `input` / `textarea` / `contenteditable`
内的按键，避免和表单冲突。

## 4. 长按倍速：需求原文的落地

需求原话是「长按倍速（松开正常）」。实现分三步：

```js
// 按下：启动定时器，450ms 后切到 3x
Player.prototype._beginLongPress = function () {
  var self = this;
  this._cancelLongPress();
  this._longPressTimer = setTimeout(function () {
    self._longPressing = true;
    self.video.playbackRate = PCFG.LONG_PRESS_RATE;   // 3x
    self.speedBadge.classList.add('mp__speed-badge--show');
    if (self.video.paused) self.video.play();
  }, PCFG.LONG_PRESS_DELAY);                          // 450ms
};

// 松开：恢复「用户自己选的倍速」，而不是硬编码 1x
Player.prototype._endLongPress = function () {
  this._cancelLongPress();
  if (this._longPressing) {
    this._longPressing = false;
    this.video.playbackRate = this._rate;             // 关键：恢复用户倍速
    this.speedBadge.classList.remove('mp__speed-badge--show');
  }
};
```

三个细节：

1. **恢复的是 `this._rate` 而非 1**。用户先把倍速调成 1.5x，再长按看 3x，
   松开后应回到 1.5x。`setRate()` 里用 `if (!this._longPressing)` 保护，
   确保长按期间点倍速菜单不会把 3x 冲掉。
2. **滑动/抬手即取消**。移动超过 6px（鼠标）或 8px（触摸）会调用
   `_cancelLongPress()`，避免「长按后又滑动」误触发倍速。
3. **长按期间暂停则自动播放**。长按往往发生在画面静止时，触发倍速即
   `video.play()`，符合直觉。

## 5. 亮度：为什么用遮罩模拟

浏览器沙箱不允许网页修改系统屏幕亮度，也没有任何标准 API。
所以「左半屏上下滑调亮度」用**叠加一层黑色遮罩 `div.mp__dim`** 实现：

```js
Player.prototype.setBrightness = function (value) {
  this._brightness = value;
  // 亮度 1 -> 遮罩全透明；亮度 0.05 -> 遮罩 95% 不透明
  this.dim.style.opacity = String(Math.max(0, Math.min(0.95, 1 - value)));
};
```

效果上等价于「画面变暗」，用户感知一致。这是移动端 Web 播放器的通行做法。

## 6. 续播机制

需求 5 要求「记录上次观看位置」。前端只负责消费，数据来自后端
`GET /api/client/videos/{id}/play-info`：

```js
v.addEventListener('loadedmetadata', function () {
  var last = Number(self.options.lastPosition || 0);
  if (last > MM.config.PLAY_REPORT.RESUME_MIN && v.duration > 0) {
    var pct = (last / v.duration) * 100;
    if (pct < MM.config.PLAY_REPORT.RESUME_TO_END) {   // 已看 95% 以上则从头
      v.currentTime = last;
      self.showCenterHint('已从 <b>' + util.formatDuration(last) + '</b> 继续播放', 2200);
    }
  }
});
```

两条阈值（`config.js` 的 `PLAY_REPORT`）：

- `RESUME_MIN = 5`：上次看到不足 5 秒不提示续播（无意义）；
- `RESUME_TO_END = 95`：上次已看到 95% 以上则从头播（避免「看完还续播到最后」。）

## 7. 观看次数统计（>10 秒才算一次）

需求 5 要求「观看次数（超过 10s 才算一次）」。这条规则**由服务端判定**，
前端只负责按心跳上报真实播放增量。

### 7.1 前端：心跳上报

进入播放页时生成一个 `segment_id`（uuid），代表「这一次播放会话」：

- 播放中每 5 秒（`PLAY_REPORT.INTERVAL`）上报一次；
- 暂停、播完、切换标签页（`visibilitychange`）、关闭页面（`beforeunload`）
  时各补一次强制上报；
- 上报内容：`position`（当前位置）、`duration`（总时长）、`delta`（本段真实播放秒数）。

**关键：`delta` 只累计真实播放时间**。拖动进度条跳着看不产生 `delta`，
所以「拖着进度条刷播放量」无效：

```js
this._reportTimer = setInterval(function () {
  if (self.video.paused) return;
  var elapsed = (Date.now() - self._lastReportAt) / 1000;
  self._lastReportAt = Date.now();
  if (elapsed > 0 && elapsed < 60) {   // 合理范围才计入
    self._delta += elapsed;
    self._watchAccum += elapsed;
  }
  self._report(false);
}, interval);
```

### 7.2 后端：会话计数（详见 `play_service.report_progress`）

服务端拿到上报后：

1. `ensure_session()` 保证 `view_session` 里存在这条会话记录；
2. `add_session_seconds(segment_id, delta)` 累加会话内观看秒数；
3. 若会话累计 ≥ 阈值（`business.view_count_threshold_seconds`，默认 **10 秒**）
   且尚未计数，则用原子置位 `UPDATE ... WHERE counted = 0` 抢占计数权，
   成功才 `video.view_count + 1`。

```sql
-- mark_session_counted 的核心：只有第一次能改成功
UPDATE view_session SET counted = 1, counted_at = NOW()
WHERE segment_id = %s AND counted = 0;
```

这个 `WHERE counted = 0` 是**并发安全的关键**：即使前端因网络重试上报了
多次「已达阈值」，也只有一次 `UPDATE` 的 `affected_rows = 1`，
从而保证**同一会话只计一次**。

### 7.3 为什么不用「进入即 +1」

- 误点击、秒退不计数，数据更干净；
- 同一会话多次心跳不重复计数；
- 拖动进度条不算数。

## 8. 进度上报与历史记录的写入

每次上报还会写 `watch_history`（`ON DUPLICATE KEY UPDATE`）：

| 字段 | 写入策略 |
| --- | --- |
| `last_position` | 覆盖为最新位置 |
| `duration` / `progress` | 覆盖 |
| `finished` | 覆盖（进度 ≥ 95% 记 1） |
| `watch_seconds` | **累加**（`watch_seconds + delta`） |
| `updated_at` | 自动更新 |

因此「续播位置」永远是最新的，而「累计观看时长」是历史总和。
首页「继续观看」板块就是按 `watch_history` 里 `progress` 在 (0, 95) 之间的记录取的。

## 9. 全屏与网页全屏的区别

| 方式 | 实现 | 特点 |
| --- | --- | --- |
| 全屏 | `requestFullscreen()`（带 webkit/ms/iOS 回退） | 真·全屏，退出用 `Esc` |
| 网页全屏 | 给容器加 `position:fixed` + `100vw/100vh`，迁到 `body` | 不改浏览器全屏状态，适合嵌入页 |

网页全屏会把播放器 DOM 临时挪到 `body` 下，并用一个注释节点占位，
退出时再插回原位 —— 避免布局跳动：

```js
this._placeholder = document.createComment('player-anchor');
c.parentNode.insertBefore(this._placeholder, c);
document.body.appendChild(c);
// 退出时
this._placeholder.parentNode.insertBefore(c, this._placeholder);
this._placeholder.parentNode.removeChild(this._placeholder);
```

## 10. 控制栏自动隐藏

- 桌面端：播放中 3 秒（`PLAYER.HIDE_DELAY`）后自动隐藏，鼠标移到控制栏保持显示；
- 移动端：**不自动隐藏**，避免误触（移动端用户靠单击显隐）。

## 11. 关键参数速查

| 参数 | 位置 | 默认 | 说明 |
| --- | --- | --- | --- |
| `LONG_PRESS_DELAY` | `player.js` 配置 | 450 | 长按触发倍速的毫秒数 |
| `LONG_PRESS_RATE` | 配置 | 3 | 长按倍速 |
| `RATES` | 配置 | `[0.5 … 3.0]` | 倍速菜单项 |
| `SEEK_STEP` | 配置 | 10 | 键盘左右键步长（秒） |
| `HIDE_DELAY` | 配置 | 3000 | 控制栏自动隐藏延时 |
| `INTERVAL` | `PLAY_REPORT` | 5 | 心跳间隔（秒） |
| `RESUME_MIN` | `PLAY_REPORT` | 5 | 小于此秒数不续播 |
| `RESUME_TO_END` | `PLAY_REPORT` | 95 | 超过此比例从头播 |
| `view_count_threshold_seconds` | `config.yaml` | 10 | 计一次播放所需秒数 |
| `heartbeat_interval_seconds` | `config.yaml` | 5 | 服务端期望心跳间隔 |

> 注意：`config.js` 的 `PLAY_REPORT.INTERVAL` 与后端
> `business.heartbeat_interval_seconds` 必须保持一致，改动时两边同步。
