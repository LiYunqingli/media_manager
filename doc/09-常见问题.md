# 09 · 常见问题 FAQ

按「症状 → 原因 → 处理」组织。先看现象，再对症下药。

## 一、启动相关

### Q1. `ModuleNotFoundError: No module named 'app'`

**原因**：启动方式不对，Python 找不到 `app` 包。

**处理**：用交付的启动脚本启动，不要直接 `uvicorn app.main:app`：

```bash
python backend/run.py
```

`run.py` 会把 `backend/` 加进 `sys.path`，并以 `app_dir=backend` 运行 uvicorn。
若一定要手动跑，需先 `cd backend` 再 `python -m uvicorn app.main:app`。

### Q2. `ModuleNotFoundError: No module named 'fastapi'`（或其他依赖）

**原因**：依赖没装，或装到了别的解释器。

**处理**：

```bash
pip install -r backend/requirements.txt
```

确认 `python -c "import fastapi, pymysql, yaml; print('ok')"` 能通过。
注意 `pip` 与 `python` 必须是同一个解释器（`python -m pip install ...` 更稳）。

### Q3. 启动报数据库连接失败 / `Can't connect to MySQL server`

**原因**：`config/config.yaml` 里的数据库信息不对，或 MySQL 没启动，或库没建。

**处理**：

1. 确认 MySQL 在跑：`mysql -h127.0.0.1 -P3306 -uroot -p -e "SELECT 1"`；
2. 检查 `config.yaml` 的 `database.host/port/user/password/name`；
3. 先执行建库脚本：`mysql -uroot -p < sql/media_manager.sql`（脚本内含 `CREATE DATABASE`）。

密码含特殊字符时建议用环境变量注入，避免 YAML 转义问题：

```bash
MM_DB_PASSWORD='p@ss#word' python backend/run.py
```

### Q4. `Address already in use` / 端口被占用

**原因**：8000 端口已被占用（常见于上一次没关干净）。

**处理**：换端口启动：

```bash
python backend/run.py --port 9000
```

Windows 下查占用：`netstat -ano | findstr :8000`，再 `taskkill /PID <pid> /F`。

### Q5. 找不到配置文件 / 改了配置不生效

**原因**：`config.yaml` 不在默认位置，或进程没重启。

**处理**：配置文件默认在 `<项目根>/config/config.yaml`。可用环境变量指定：

```bash
MM_CONFIG=/path/to/config.yaml python backend/run.py
```

`get_settings()` 带 `lru_cache`，**改配置必须重启进程**。

## 二、数据库相关

### Q6. 中文变问号 / 乱码

**原因**：连接字符集不对。

**处理**：`config.yaml` 的 `database.charset` 保持 `utf8mb4`；
建库脚本已声明 `DEFAULT CHARSET=utf8mb4`。若库是旧建的，手动改：

```sql
ALTER DATABASE media_manager CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### Q7. `Too many connections` / 连接池耗尽

**原因**：并发高或某处连接未释放。

**处理**：调大 `database.pool_max`；确认业务代码用 `get_cursor()` / `transaction()`
的上下文管理器（会自动归还连接），不要手动 `raw_connection()` 后忘记关闭。

### Q8. 时间差 8 小时

**原因**：时区未统一。

**处理**：`config.yaml` 的 `app.timezone` 设为 `Asia/Shanghai`；
MySQL 侧确认 `SELECT @@global.time_zone` 与业务一致。

## 三、上传相关

### Q9. 上传到一半失败 / 页面刷新后要重传

**原因**：网络中断属于正常；刷新后**不该**重传。

**处理**：本系统支持断点续传。刷新管理端上传页，会从
`upload_session` + `upload_chunk` 恢复进度，只补传缺失分片。若恢复后从头传，
检查分片落盘是否成功（`storage/chunks/<upload_id>/`）。

### Q10. 合并失败 `UPLOAD_MERGE_FAILED`

**排查顺序**：

1. 分片是否齐全：`GET /api/admin/upload/{id}/progress` 看 `uploaded_chunks == total_chunks`；
2. 磁盘空间是否足够（合并需要一份完整文件的空间）；
3. 查看后端日志（`storage/logs/backend.log`）中合并线程的异常堆栈。

### Q11. 明明是新文件却「秒传」了

**原因**：秒传用「文件名 + 大小 + 首 1MB 的 SHA-256」做弱哈希，理论上存在碰撞可能。

**处理**：弱哈希是为了性能的权衡（对大文件算完整哈希很慢）。
若业务上不能容忍，可在 `upload_service.init_upload` 里改为完整文件哈希。

### Q12. 上传成功但列表里没有

**原因**：多半是「未关联分类」或状态为禁用。

**处理**：合并时提交了 `category_id` 与 `title`，确认分类存在且未被禁用；
管理端视频列表支持按状态筛选，检查 `video.status`。

## 四、封面相关

### Q13. 上传后没有生成封面

**原因**：封面抽取有**三级降级**，当前环境可能都不满足。

**处理**：

| 后端 | 依赖 | 能力 |
| --- | --- | --- |
| `av`（PyAV） | `pip install av` | 抽帧 + 完整元数据 |
| `cv2`（OpenCV） | `requirements.txt` 已含 `opencv-python-headless` | 抽帧 + 元数据 |
| `builtin`（纯 Python） | 无 | **仅时长**，无法抽帧 |

`config.yaml` 的 `media.backend` 默认 `auto`，按 av → cv2 → builtin 顺序尝试。

**如果封面没生成**：说明当前只降级到 `builtin`。装上 OpenCV 即可：

```bash
pip install opencv-python-headless
```

管理端「系统信息」页会明确显示当前生效的媒体后端。
也可以对已有视频手动「重新生成封面」（视频列表 → 更多操作）。

### Q14. 装了大写 `cv2` 仍不抽帧

**原因**：`opencv-python`（带 GUI）与 `opencv-python-headless` 冲突安装，
或版本不匹配 Python。

**处理**：先 `pip uninstall opencv-python opencv-python-headless`，
再只装 headless 版。输出解析走后端日志可见 `_probe_cv2` 的报错。

## 五、播放相关

### Q15. 视频加载失败 / 黑屏

**原因**：编码或封装不被浏览器支持。浏览器对 `<video>` 的支持有限
（H.264/AAC 最稳，部分浏览器不支持 MKV/AVI/FLV）。

**处理**：源文件尽量用 **MP4（H.264 + AAC）**。系统允许上传 MKV 等格式，
但能否在浏览器播放取决于编码，建议上传前转码。

### Q16. 自动播放没生效

**原因**：浏览器策略拦截「有声音的自动播放」。

**处理**：属正常现象，播放器会捕获异常并提示「点击播放按钮开始播放」。
要么用户手动点，要么给视频 `muted` 后自动播放。

### Q17. 全屏按钮没反应

**原因**：iOS Safari 不支持对容器 `requestFullscreen`。

**处理**：播放器已内置回退链：容器全屏 → `webkitRequestFullscreen` →
`video.webkitEnterFullscreen`（iOS）。若都被拒绝，用「网页全屏」按钮代替，
它只改布局不吃浏览器 API，全平台可用。

### Q18. 播放次数一直不涨

**原因**：计一次播放需要**同一会话累计观看 ≥ 10 秒**（`view_count_threshold_seconds`）。

**排查**：

1. 观看是否真的超过 10 秒（拖动进度条跳着看**不算**，只有真实播放增量计入）；
2. 心跳是否正常：浏览器 Network 里应每 5 秒一次 `play-report` 请求；
3. 阈值是否为 0（会被当作立即计数）：检查 `config.yaml`。

### Q19. 续播位置不对 / 每次都从头

**原因**：进度未上报，或上次看到 95% 以上（会从头播）。

**处理**：检查 `watch_history` 表是否有该用户+视频的记录；
`PLAY_REPORT.RESUME_TO_END = 95` 表示看完的片子重进从头播，这是设计行为。

## 六、权限相关

### Q20. 某个用户看不到视频 / 看不到分类

**处理**：这是权限模型问题，完整排查见 [07-权限模型](./07-权限模型.md) 第 11 节。
最快的定位方式：调 `GET /api/admin/users/{id}/permissions` 看该用户的实际规则。

**三个高频误判**：

- 「没设限制却全不可见」→ 存在分类白名单，但白名单里的分类被禁用了；
- 「想限制却全可见」→ 该用户**没有**任何 `allow=1` 分类记录，默认全放开；
- 「拉黑了还能看」→ 该视频同时在白名单，被规范化时白名单优先。

## 七、手机端访问

### Q21. 手机浏览器打不开

**原因**：多数是监听地址或防火墙。

**处理**：

1. `config.yaml` 的 `app.host` 设为 `0.0.0.0`（不要用 `127.0.0.1`）；
2. 手机与电脑连同一 Wi-Fi；
3. 查电脑局域网 IP：`ipconfig`（Windows）/ `ifconfig`（Mac/Linux）；
4. 手机访问 `http://<电脑IP>:8000`；
5. 打不开就放行防火墙入站 8000 端口（Windows 首次运行会有弹窗，需允许）。

### Q22. 手机能打开页面但视频不播

**排查**：确认视频编码是 H.264/AAC（见 Q15）；iOS 还需 `playsinline`
（播放器 `<video>` 已带 `playsinline webkit-playsinline x5-playsinline`）。

> 注：视频播放本身**不需要** HTTPS 安全上下文。只有当你的功能依赖
> 定位/摄像头/麦克风时才需要 HTTPS。

## 八、前端相关

### Q23. 页面白屏 / 控制台报 Vue 组件解析错误

**原因**：in-DOM 模板违规（自闭合标签或大驼峰组件名）。

**处理**：见 [08-开发规范](./08-开发规范.md) 第 4 节的三条铁律。
改完用 HTML5 解析器复核。

### Q24. 页面样式全无 / 图标显示成方块

**原因**：`frontend/static/vendor/` 里的本地库缺失（离线环境常见）。

**处理**：运行本地化脚本重新拉取：

```bash
python scripts/fetch_vendor.py
```

它会下载 Vue / Element Plus / Vant 及其 CSS、中英文语言包、图标到
`frontend/static/vendor/`。

### Q25. 请求一律 401

**原因**：token 丢失或过期（默认 7 天）。

**处理**：清掉 `localStorage` 的 `mm_token` / `mm_user` 重新登录；
或核对 `security.token_expire_minutes`。

### Q26. 页面能打开，但顶栏/侧边栏整个消失、内容裸露在页面上

**原因**：外壳组件 `web-shell`（用户端）/ `admin-shell`（管理端）**没有被注册**。
Vue 会把它们当作未知元素，只把插槽内容原样渲染出来，不套布局 ——
表现就是「页面能显示，但 UI 全乱」。

**处理**：这是本项目踩过的坑，根因在 `components-web.js` 的
`MM.registerComponents()`：它必须遍历**全局注册表 `MM.components`**，
而不是本文件内部的闭包集合。因为 `web-shell` / `admin-shell` 是分别在
`layout-web.js` / `admin-common.js` 里、于 `components-web.js` **之后**
追加到 `MM.components` 的；注册函数若只看闭包集合，就会把它们全部漏掉。

同时确认脚本引入正确：

| 端 | 必须引入 |
| --- | --- |
| 用户端页面 | `components-web.js` + `layout-web.js` |
| 管理端页面 | `components-web.js` + `admin-common.js` |

**快速自检**（浏览器控制台，任选其一）：

```js
Object.keys(MM.components);      // 是否包含 web-shell / admin-shell
// 或看控制台是否有 [Vue warn] Failed to resolve component: web-shell
```

## 九、WebSocket 相关

### Q27. 上传进度推送不动，但进度条还在走

**原因**：WebSocket 被代理/防火墙拦截，连接失败。

**处理**：**这是设计内的降级行为**。前端在 WS 连不上时自动切到 HTTP 轮询
（`GET /api/admin/upload/{id}/progress`，频率自适应 0.2s~2s），进度照常更新。
若想恢复 WS，检查反向代理是否转发 `/ws/` 路径（需支持 Upgrade）。

## 十、其他

### Q28. 日志在哪

- 控制台：启动终端（彩色输出）；
- 文件：`storage/logs/backend.log`（按 10MB 轮转，保留 5 份）。

### Q29. 线上要不要开 `/docs`

`config.yaml` 的 `dev.enable_api_docs` 控制 FastAPI 自带的 `/docs` 与 `/redoc`。
生产建议设为 `false`。`dev.expose_traceback` 同理，生产必须为 `false`，
否则异常堆栈会返回给前端。

### Q30. 媒体文件存在哪

全部在 `storage/` 下：`videos/`（正式视频）、`covers/`（封面）、`avatars/`（头像）、
`chunks/`（上传分片，合并后清除）、`tmp/`、`logs/`。
通过 URL `/media/videos/...`、`/media/covers/...` 访问。
`storage/` 不入版本库（见 `.gitignore`），迁移时记得单独拷贝。
