# 08 · 开发规范

二次开发前先读这份。规则不是教条，是为了让代码保持「同一只手写出来」的观感，
降低维护成本。

## 1. 后端分层约定

严格四层，**只允许向下依赖，不允许跨层**：

```
api/          （HTTP 层）参数校验 → 调 service → 组装响应
  ↓
services/     （业务层）业务规则、事务编排、权限断言、调用多个 repo
  ↓
repositories/ （数据层）纯 SQL，只处理表，不写业务
  ↓
db/           （连接层）连接池、游标、事务
```

各层红线：

| 层 | 该做 | 不该做 |
| --- | --- | --- |
| `api/` | 声明路由、Pydantic 校验、权限依赖注入、调 service、`return ok(...)` | 写 SQL、写业务判断、直接操作连接 |
| `services/` | 业务逻辑、组装数据、抛 `BizError`、调多个 repo、开事务 | 碰 `Request` 对象、拼 HTTP 响应、写 SQL 字符串 |
| `repositories/` | 拼 SQL、读写表、返回 dict/list | 业务校验、抛业务错误、处理权限 |
| `db/` | 连接池、`query_all` / `execute` / `transaction` | 知道任何业务表名以外的语义 |

要点：

- **repo 只依赖 `db.session` 提供的高阶函数**（`query_all/query_one/query_value/count/exists/execute/execute_return_id/execute_many`），不自己 `cursor.execute`（事务场景除外，用 `with db.transaction() as cur`）。
- **参数化查询**是硬规定。任何用户输入进 SQL 必须用 `%s` 占位，禁止 f-string 拼值。
  只有「占位符个数」可以用 f-string 生成（如 `placeholders(n)`）。
- 动态 `IN` / `NOT IN` 统一用 `repositories/_sql.py` 的
  `placeholders()` / `in_clause()` / `not_in_clause()`，不要各写各的。

## 2. 命名规范

### Python

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 模块 / 包 | 小写下划线 | `permission_service.py` |
| 类 | 大驼峰 | `ConnectionPool`、`Visibility` |
| 函数 / 变量 | 小写下划线 | `get_visible_video` |
| 常量 / 模块级映射 | 大写 | `STAGE_RANGE`、`_LIST_COLUMNS` |
| 「私有」 | 前置单下划线 | `_visibility`、`_not_in`、`_MESSAGES` |
| 类型别名 | 大写开头 | `CurrentUser`、`PageParams` |

- repo 函数动词前缀约定：`find_*` / `list_*` / `count_*` / `create` / `update` / `delete`。
- 布尔语义字段一律 `is_*` / `has_*`（如 `is_admin`）。
- 全部模块 `from __future__ import annotations` + 类型标注。

### 前端 JS

- 全局命名空间挂在 `window.MM` 下，模块用 **IIFE** 包裹，`'use strict'`：

```js
(function (global) {
  'use strict';
  var MM = (global.MM = global.MM || {});
  // ... 定义 MM.xxx
})(window);
```

- 结构：`MM.config` / `MM.util` / `MM.ui` / `MM.http` / `MM.auth` / `MM.Player` / `MM.ChunkUploader` / `MM.components`。
- DOM 类名一律 `mm-` 前缀（公共）或模块前缀（如播放器 `mp__`、管理端 `admin-`）。
- CSS 变量一律 `--mm-` 前缀。

### 数据库

- 表名：小写下划线、单数名词（`video` 而非 `videos`；关联表用 `a_b` 形式，如 `user_category_rule`）。
- 字段：小写下划线；布尔字段用 `tinyint` 且命名说清语义（`allow` / `status` / `finished`）。
- 每张表必备 `created_at` / `updated_at`（`DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE`）。

## 3. 响应体与错误码规范

**唯一契约**（见 `core/response.py`）：

```json
// 成功
{"code": 0, "msg": "ok", "data": {...}}
// 失败
{"code": 2004, "msg": "用户名或密码错误", "data": null}
// 分页
{"code": 0, "msg": "ok", "data": {"list": [...], "total": 128, "page": 1, "page_size": 20, "pages": 7}}
```

- HTTP 状态码表达传输层语义；**前端主要看 `code`**。
- 业务错误一律抛 `BizError(ErrorCode.XXX)`，由全局异常处理器转响应体，
  **禁止在路由里手写 `JSONResponse` 表达业务失败**。
- 新增错误码：在 `ErrorCode` 里按分段添加（1xxx 通用 / 2xxx 认证 / 3xxx 权限 /
  4xxx 资源 / 5xxx 业务 / 9xxx 系统），并在 `_HTTP_STATUS` 与 `_MESSAGES` 同步登记。

## 4. 前端多页规范（三条铁律）

项目用「多个 HTML 页面 + Vue UMD」而非 SPA。浏览器会先解析 HTML，
**Vue 拿到的是浏览器解析后的 DOM**，因此有三条必须遵守的规则：

1. **自闭合标签无效**。in-DOM 模板必须写完整闭合标签：

   ```html
   <!-- ✗ 错误：浏览器会当作未闭合，后续兄弟节点被吞进去 -->
   <el-option v-for="..." :key="..." :label="..." :value="..." />

   <!-- ✓ 正确 -->
   <el-option v-for="..." :key="..." :label="..." :value="..."></el-option>
   ```

2. **组件名必须全小写 kebab-case**。in-DOM 模板会被 HTML 解析器转小写，
   大驼峰组件名匹配不上：

   ```html
   <!-- ✗ 错误 -->
   <ArrowDown />
   <!-- ✓ 正确 -->
   <arrow-down></arrow-down>
   ```

3. **`<table>` / `<ul>` 等受限元素里不能直接放自定义组件**。
   能用 `<div>` + CSS 布局替代就替代；实在需要时用 `is` 属性。

> 交付前务必用 HTML5 规范级解析器（如 `html5lib`）复核：自定义元素不得自我嵌套、
> `el-option` / `el-dropdown-item` 不得相互嵌套、`<template>` 内容保留。

### 组件注册约定（血泪教训）

全局组件统一登记在 `MM.components` 上，由 `components-web.js` 的
`MM.registerComponents(app)` 一次性注册到 Vue 应用。两条硬规则：

1. **`registerComponents()` 只能遍历 `MM.components`，不得遍历文件内的闭包变量。**
   `web-shell`（定义在 `layout-web.js`）与 `admin-shell`（定义在 `admin-common.js`）
   都是在 `components-web.js` **之后**才追加进 `MM.components` 的。注册函数若只看
   闭包集合，这些外壳组件会全部漏注册 —— Vue 会把它们当未知元素，页面顶栏/侧边栏
   消失、内容裸露，也就是「UI 全乱」。
2. **往注册表加组件用「合并」而非「覆盖」。**
   `components-web.js` 的写法是 `MM.components = MM.components || {}` 再逐项赋值，
   禁止写成 `MM.components = comps` —— 后者会抹掉在此之前登记的一切。

对应的页面脚本引入清单（顺序不能反）：

| 端 | 必须引入 |
| --- | --- |
| 用户端页面 | `components-web.js` → `layout-web.js` |
| 管理端页面 | `components-web.js` → `admin-common.js` |

### 页面结构约定

- 每页 `<head>` 里的 CSS/JS 引用顺序固定：
  `common.css` → 页面/端专属 css → vendor 库 → `config.js` → `utils.js` → `ui.js` → `request.js` → 组件 → 布局 → 页面内联脚本。
- 页面里不写 `<script type="module">`（离线 + file/reload 场景易出问题），
  统一用普通 `<script>`，靠 `window.MM` 共享。
- 所有 API 调用走 `MM.http`，不要在页面里裸用 `fetch`（拿不到统一的 token 注入与错误提示）。

## 5. 主题与样式约定

- 暗 / 亮双主题由 `data-theme` 驱动，同时同步 `dark` 属性（Element Plus）
  与 `van-theme-dark`（Vant）：

  ```js
  document.documentElement.setAttribute('data-theme', theme);
  document.documentElement.classList.toggle('dark', theme === 'dark');
  document.documentElement.classList.toggle('van-theme-dark', theme === 'dark');
  ```

- **颜色只能用设计变量**（`--mm-*`），禁止在业务样式里写死十六进制色值，
  否则主题切换会失效。
- 禁止 emoji 充当功能图标（已有 Element Plus Icons / Vant Icons）。

## 6. 配置规范

- 全部可调参数集中在 `config/config.yaml`，支持 `${ENV_NAME:default}` 占位符。
- 代码里通过 `get_settings()`（带 `lru_cache`）读取，**不要散落 `os.getenv`**。
- 相对路径统一经 `resolve_path()` 解析为「相对项目根」的绝对路径。
- 前端参数集中在 `frontend/static/js/config.js` 的 `MM.config`。
- **前后端共享的参数要双边同步**：如播放心跳间隔
  （`business.heartbeat_interval_seconds` ↔ `PLAY_REPORT.INTERVAL`）。

## 7. 数据库变更规约（重要）

按需求约定执行，**不要直接改基线文件**：

| 次数 | 操作 |
| --- | --- |
| 第 1 次变更 | 只写 `sql/update.sql` |
| 第 2 次变更 | 追加到 `sql/update.sql`（同文件累积） |
| 第 3 次变更 | 把 `sql/update.sql` 现有内容**追加到 `sql/media_manager.sql` 末尾**，然后清空 `update.sql` 重写本次变更 |
| 第 4 次起 | 重复上述循环 |

`update.sql` 顶部维护一行计数注释：`【当前变更计数】N / 3`。
每次提交前更新该计数。

## 8. 提交流程

- 本项目 Git 仓库根在 `media_manager/`（见 `.gitignore`）。
- **只有收到明确的「提交」指令才执行 `git commit`**，不要自作主张提交。
- 提交信息用「类型: 简述」格式，参考：`feat:` / `fix:` / `docs:` / `refactor:` / `style:` / `chore:`。
- 提交前自查清单：

  - [ ] `python -m compileall backend/app backend/run.py` 无错误
  - [ ] 改动的 JS 跑过 `node --check`
  - [ ] 改动的 HTML 过一遍 HTML5 解析校验
  - [ ] 新增/变更接口同步更新 `doc/03-API接口文档.md`
  - [ ] 改表同步 `sql/` 与 `doc/02-数据库设计.md`
  - [ ] `storage/` 不在暂存区

## 9. 禁止事项清单

- ✗ 在 `api/` 里写 SQL。
- ✗ 在 repo 里做业务校验或抛业务错误。
- ✗ 用 f-string 把用户输入拼进 SQL。
- ✗ 在业务 CSS 里写死颜色值。
- ✗ 在 in-DOM 模板里用自闭合标签或大驼峰组件名。
- ✗ 在页面里裸用 `fetch` 绕过 `MM.http`。
- ✗ 无明确指令时执行 `git commit`。
- ✗ 直接改 `sql/media_manager.sql` 做增量变更（增量只写 `update.sql`）。
