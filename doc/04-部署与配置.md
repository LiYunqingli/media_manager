# 04 · 部署与配置

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| Python | **3.10+**（推荐 3.11/3.12） | 代码使用了 `X \| None` 类型语法 |
| MySQL | **5.7+ / 8.x** | 需要 InnoDB 与 utf8mb4 |
| 浏览器 | Chrome / Edge 90+、Firefox、Safari 15+ | 播放器依赖 `aspect-ratio`、`requestFullscreen` |
| 可选 | `opencv-python-headless` 或 `av` | 用于**自动抽取关键帧封面** |

> **无需安装 ffmpeg 二进制**。本项目不调用外部 ffmpeg 进程；
> 时长/分辨率探测有纯 Python 的 MP4 解析兜底。

## 2. 部署步骤

### 2.1 建库

```bash
mysql -u root -p < sql/media_manager.sql
```

脚本会自动创建数据库 `media_manager`（若不存在）并写入 10 张表、3 个内置账号、6 个示例分类，
以及 `user1` 的分类白名单示例。

### 2.2 配置数据库连接

编辑 `config/config.yaml`：

```yaml
database:
  host: 127.0.0.1
  port: 3306
  user: root
  password: "${MM_DB_PASSWORD:你的密码}"
  name: media_manager
```

支持 `${环境变量:默认值}` 语法。不想把密码写进文件时可只设环境变量：

```bash
# Linux / macOS
export MM_DB_PASSWORD='your-password'
# Windows PowerShell
$env:MM_DB_PASSWORD = 'your-password'
```

同时请**务必修改** `security.secret_key`（JWT 签名密钥）。

### 2.3 安装依赖

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r backend/requirements.txt
```

最小可用依赖：`fastapi`、`uvicorn[standard]`、`python-multipart`、`PyMySQL`、`PyYAML`、`pydantic`。

抽帧封面能力取决于 `opencv-python-headless`（推荐）或 `av`：

```bash
pip install opencv-python-headless     # 抽帧首选，安装体积适中
# 或
pip install av Pillow                  # PyAV 路线，探测更精确
```

没装任何一个也能正常运行：上传时视频照常入库，只是**不会自动生成封面**，
前端会退化为渐变色 + 标题首字的占位图。管理端「系统信息」页会明确提示缺少哪个库。

### 2.4 启动

```bash
python backend/run.py
```

可选参数：

```bash
python backend/run.py --host 127.0.0.1 --port 9000     # 覆盖监听地址/端口
python backend/run.py --reload                          # 开发热重载
python backend/run.py --workers 4                       # 多进程（与 --reload 互斥）
python backend/run.py --log-level debug
```

也可以用 uvicorn 直接启动：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --app-dir backend
```

### 2.5 访问入口

| 入口 | 地址 | 内置账号 |
| --- | --- | --- |
| 用户端 | http://localhost:8000/ | `user1` / `user123` |
| 管理端 | http://localhost:8000/admin/ | `admin` / `admin123` |
| 接口文档 | http://localhost:8000/docs | — |

**首次登录请立刻修改 admin 密码**（管理端右上角退出 → 用用户端个人中心改，或直接在数据库里重置）。

## 3. 配置项说明

完整注释见 `config/config.yaml`，以下为关键项。

### 3.1 `app`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `0.0.0.0` | 局域网手机访问必须保持 `0.0.0.0` |
| `port` | `8000` | 监听端口 |
| `default_site` | `web` | 访问 `/` 时跳到哪一端：`web` / `admin` / `none` |
| `cors_origins` | `["*"]` | 前后端分离部署时按需收紧 |

### 3.2 `security`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `secret_key` | 占位值 | **JWT 签名密钥，上线必须改** |
| `token_expire_minutes` | `10080` | 登录有效期（分钟），默认 7 天 |
| `password_rounds` | `120000` | PBKDF2 迭代次数 |
| `login_max_fail` | `0` | 登录失败锁定次数，0 表示不锁定 |

### 3.3 `storage`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `root` | `./storage` | 相对项目根目录解析；也可写绝对路径 |
| `allow_video_ext` | mp4/mkv/mov/… | 上传白名单 |
| `max_file_size` | `0`（不限） | 单文件字节上限 |

目录用途：`videos/` 正式视频、`covers/` 封面、`avatars/` 头像、
`chunks/<upload_id>/` 分片临时目录、`tmp/`、`logs/`。

### 3.4 `upload`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `chunk_size` | `5242880`（5MB） | 前端切分依据，服务端也会回传 |
| `session_expire_hours` | `24` | 未完成会话保留时长 |
| `verify_chunks` | `true` | 合并前校验分片数量与存在性 |
| `remove_chunks_after_merge` | `true` | 合并成功后清理分片 |
| `max_chunks` | `20000` | 分片数上限（防滥用） |
| `progress_interval_ms` | `300` | 合并进度写库节流间隔 |

> 分片大小建议 5–10MB。太小会让请求数暴增，太大会让单片重传代价变高。

### 3.5 `media`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `backend` | `auto` | `auto` / `av` / `cv2` / `builtin`，强制指定处理后端 |
| `cover_seek_seconds` | `3.0` | 抽帧时间点（从该时刻找最近关键帧） |
| `cover_fallback_seeks` | `[1.0, 0.0]` | 抽帧失败的回退时间点 |
| `cover_max_width/height` | 1280×720 | 封面最长边限制 |
| `cover_quality` | `3` | JPEG 质量（越小越好） |

### 3.6 `business`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `view_count_threshold_seconds` | `10` | **单次会话累计观看 ≥10 秒记 1 次播放**（需求 5） |
| `heartbeat_interval_seconds` | `5` | 前端上报间隔 |
| `finished_percent` | `95` | 达到该进度视为看完 |
| `continue_watch_limit` | `12` | 「继续观看」条数 |
| `related_limit` | `8` | 相关推荐条数 |
| `home_section_size` | `12` | 首页每个分类板块的视频数 |

### 3.7 `dev`

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enable_api_docs` | `true` | 是否开放 `/docs` 与 `/redoc`（生产可关闭） |
| `expose_traceback` | `false` | 500 响应是否返回异常堆栈（仅调试时开） |

## 4. 局域网 / 手机访问

需求 8 要求用户端兼容手机，开发时通常用手机连电脑的内网地址：

1. `config.yaml` 中 `app.host` 保持 `0.0.0.0`；
2. 查本机内网 IP：

   ```bash
   # Windows
   ipconfig | findstr IPv4
   # Linux / macOS
   ifconfig | grep "inet " | grep -v 127.0.0.1
   ```

3. 放通防火墙端口（Windows 首次启动时允许"专用网络"访问即可；或手动）：

   ```powershell
   New-NetFirewallRule -DisplayName "MediaManager 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
   ```

4. 手机浏览器访问 `http://<内网IP>:8000/`。

**注意**：前端所有请求都用相对路径（`/api/...`、`/static/...`），
因此换任何 IP/端口访问都不需要改代码。

> 如果后续需要 HTTPS（例如要调用需要安全上下文的能力），可参考同机其他项目的做法挂反向代理。

## 5. 数据备份

媒体文件和数据库分开备份：

```bash
# 数据库
mysqldump -u root -p media_manager > backup_$(date +%Y%m%d).sql

# 媒体文件（目录可能很大，建议增量同步）
rsync -av storage/videos/ /backup/videos/
```

`storage/` 目录不入版本库（见 `.gitignore`），部署迁移时单独拷贝即可。

## 6. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `未找到配置文件` | 确认 `config/config.yaml` 存在，或用 `MM_CONFIG` 指定路径 |
| 启动日志出现 `数据库连接失败` | 检查 `database` 段；确认 MySQL 已启动、账号有权限、库已创建。服务仍会启动，接口会返回 `code=9002` |
| 登录返回 `code=2004` 但密码没错 | 检查数据库里 `password` 字段是否为 `pbkdf2_sha256$...` 格式；若被手动改成明文会校验失败 |
| 页面白屏 | 打开浏览器控制台看报错；确认 `frontend/static/vendor/` 下的库文件存在（若缺失执行 `python scripts/fetch_vendor.py`） |
| 上传完成但没封面 | 未安装 `opencv-python-headless` / `av`。管理端「系统信息」页可确认；也可给单个视频上传自定义封面 |
| 上传到 100% 后卡在 merging | 查看后端日志；通常是分片不完整。可点"续传/重试"重新走一遍（会跳过已上传分片） |
| 视频无法拖动进度 | 检查 `/media/videos/**` 是否被反向代理破坏了 Range 请求（Nginx 需保留 `Range` 头） |
| 手机端页面错位 | 确认 `<meta name="viewport">` 未被修改；`static/css/web.css` 中 767px 断点负责移动端适配 |
| 用户看不到某分类 | 去管理端「用户与权限」检查白名单是否被设置成了不含该分类的集合。详见 [07-权限模型](./07-权限模型.md) |
