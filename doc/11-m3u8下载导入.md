# m3u8 链接下载导入

`scripts/fetch_tools.py` + `download_service` 构成的第三条入库入口：**不给文件，给链接**。
服务端调 [`N_m3u8DL-RE`](https://github.com/nilaoda/N_m3u8DL-RE) 把 HLS/DASH 流下载并混流成 mp4，
再走与分片上传、批量导入**完全相同**的入库链路。

## 1. 什么时候用它

| 场景 | 用哪个 |
| --- | --- |
| 视频源是 HLS/DASH 播放列表（`.m3u8` / `.mpd`），本地没有文件 | **本功能** |
| 浏览器插件/脚本要往系统里投递任务，不想存管理员密码 | **本功能**（`X-API-Token`） |
| 服务器磁盘上已有视频文件 | 批量导入工具（[10](./10-批量导入工具.md)） |
| 管理员在浏览器里传本地文件 | 分片上传（[05](./05-分片上传设计.md)） |

和另外两条入口的关系：

```
分片上传   ──┐
批量导入   ──┼─→ ingest_service.ingest_file() → 容器校验/转封装 → 探测 → 封面 → video 表
m3u8 下载  ──┘
```

入库之后的处理完全一致，所以不存在「下载进来的视频不会自动转封装」这类行为漂移。

## 2. 准备工具链

本功能依赖两个外部可执行文件，都在 `tools/` 下（已加进 `.gitignore`，**不入库**）：

```
tools/
  ├─ N_m3u8DL-RE/N_m3u8DL-RE.exe   # 下载器本体
  ├─ ffmpeg/bin/ffmpeg.exe          # 混流（音视频分离的流必需）
  ├─ ffmpeg/bin/ffprobe.exe
  └─ manifest.json                  # 版本/下载时间/来源 URL 记录
```

一行命令拉取（脚本自动识别 Windows / Linux / macOS 与 CPU 架构）：

```bash
python scripts/fetch_tools.py            # 两个都装（已存在则跳过）
python scripts/fetch_tools.py --only m3u8    # 只装下载器
python scripts/fetch_tools.py --force        # 强制重下
python scripts/fetch_tools.py --list         # 只看有哪些资产、当前装了什么
```

脚本做的事：请求 GitHub `/releases/latest` 拿 tag → 从 `expanded_assets` 页面正则提取
匹配当前平台的资产名（`win-x64` / `linux-x64` / `osx-arm64` …）→ 下载到临时文件 →
**先解压到临时目录、成功后才替换正式目录**（不会出现下载中断导致工具损坏）。
ffmpeg 走 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/)（失败回退 BtbN 的 GitHub release），
只挑 `ffmpeg` / `ffprobe` 两个二进制，不带文档和头文件。

> 没有外网、或想手工放置：把 `N_m3u8DL-RE.exe` 与 `ffmpeg.exe` 放到上面那两个路径即可，
> 然后在 `config.yaml` 里把 `download.binary` / `download.ffmpeg_binary` 指向实际位置。

启动服务后在管理端「导入方式 → m3u8 下载」页面顶部会显示工具链状态；
也可直接查：

```
GET /api/admin/download/tools
```

未就绪时该接口返回 `code=5011`，新建任务同样拒绝，**不会**等到任务跑起来才报错。

## 3. 配置项（`config/config.yaml` → `download`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关。关闭后接口一律返回 `code=5010`，前端隐藏该标签页 |
| `binary` | `tools/N_m3u8DL-RE/N_m3u8DL-RE.exe` | 下载器路径（相对项目根或绝对路径） |
| `ffmpeg_binary` | 空 | 留空则按 `tools/ffmpeg/bin/ffmpeg(.exe)` → `PATH` 顺序探测 |
| `max_concurrent` | `2` | 同时运行的下载任务数（进程级并发），超出排队 |
| `threads` | `8` | 单任务分片下载线程数 |
| `download_retry` | `3` | 分片失败重试次数 |
| `timeout_seconds` | `7200` | 单任务最长运行秒数，超时强杀进程树；`0` = 不限 |
| `extra_args` | `[]` | 透传给下载器的额外参数，全局兜底用（如固定 UA） |
| `auto_select` | `true` | 自动选所有类型的最佳轨道，多码率列表必开 |
| `mux_format` | `mp4` | 完成后混流容器：`mp4` / `mkv` / 空串（不混流）。缺 ffmpeg 时自动降级为不混流 |
| `cover_max_bytes` | `20971520` | 远程封面最大体积，超限忽略；`0` = 不限 |
| `record_hash` | `true` | 下载完写 `upload_session` 台账（供网页端秒传命中） |
| `default_category_id` | `0` | 兜底分类；`0` = 必须显式指定分类 |
| `api_token` | `""` | **插件令牌**，见 §5；空 = 关闭免登录通道 |
| `api_user_id` | `0` | 令牌调用时任务归属用户；`0` = 自动取第一个管理员 |

`api_token` 支持环境变量注入，不要把令牌提交到仓库：

```yaml
api_token: "${MM_DOWNLOAD_API_TOKEN:}"
```

## 4. 用法 A：管理端页面

管理端 → **导入方式 → m3u8 下载** 标签页：

- 顶部横幅显示工具链状态（未就绪时给出 `fetch_tools.py` 命令）；
- 表单：**链接**（必填）、**视频名称**（留空则取链接末段）、**分类**（必填）、
  **封面地址**（留空则自动抽帧）、简介、排序、**附加请求头**（如 `Referer: ...`，一行一条）、
  「已下载过也重新下载」；
- 下半部分是任务卡片列表：阶段轨道、进度条、已下载/总量/速度/剩余时间、
  来源标记（`手动` / `插件`）；进行中的可**取消**，失败/取消的可**重试**，
  任意状态可**删除记录**；
- 「清理历史」一键删掉 7 天前的失败/取消任务。

页面按 2 秒轮询列表接口刷新，切到别的标签页会自动停掉轮询。

### 4.1 从嗅探插件快捷填表

`extension/`（Chrome MV3 扩展）抓到页面请求后，弹窗底部「一键复制」会输出一段键值对：

```
# MediaManager 下载任务
url=https://cdn.example.com/hls/index.m3u8?token=abc
title=T38-071 中文字幕
cover=https://assets.example.com/videos/t38-071/preview.jpg
```

回到本页有两种填法，效果一样：

- 点链接输入框右边的 **「一键粘贴」**（直接读剪贴板，省一次 Ctrl+V）；
- 或 **Ctrl+V 直接粘进链接输入框** —— 识别到键值对会自动拆开，一次填好三个字段。

之后只需再选分类就能提交。

格式约定 —— **生产端与消费端是一对写死的约定，改格式必须两边一起改**：

| 行 | 说明 |
| --- | --- |
| `#` 开头 | 注释，解析时忽略 |
| `url=` | 必须存在；缺了整段就按普通文本处理（所以粘一条纯链接不会被拦） |
| `title=` / `cover=` | 可选；为空的行**不输出**，也就不会把页面上已填的内容覆盖成空 |
| `cover_url=` | `cover` 的别名，两种写法都认 |
| 同键重复 | 取第一条 |
| 键名大小写 / 前后空格 | 都容忍 |

生产端是 `extension/task-text.js` 的 `buildTaskText()`，
消费端是 `frontend/admin/upload.html` 的 `parseTaskText()` / `applyDlTaskText()`。

> 粘贴识别拦的是 `paste` 事件、读的是 `clipboardData`：`<input>` 是**单行元素**，
> 多行文本直接粘进去换行会被浏览器吃掉，等 `input` 事件触发时已经分不出行了。

## 5. 用法 B：API（给浏览器插件用）

### 5.1 免登录令牌通道

插件里让用户扫码登录管理端不现实，所以给了令牌通道：在 `config.yaml` 设

```yaml
download:
  api_token: "改成一串随机长字符串"
```

然后任何请求带上该请求头即可，**无需 JWT**：

```
X-API-Token: <令牌>
```

校验用**常量时间比较**（`secrets.compare_digest`），避免时序侧信道。
令牌为空时该通道关闭，此时只能走管理员 JWT。
令牌调用产生的任务 `source` 字段为 `api`，管理端页面会打上「插件」标记，便于追溯。

### 5.2 投递任务

```bash
curl -X POST http://127.0.0.1:8000/api/admin/download/m3u8 \
  -H "X-API-Token: <令牌>" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/hls/index.m3u8",
    "title": "示例影片",
    "cover_url": "https://example.com/poster.jpg",
    "category_id": 1
  }'
```

**最小可用入参只有 `url` + `title` + `cover_url`**，插件一句话就能投递。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `url` | string | ✅ | m3u8/mpd 地址，只接受 `http` / `https` |
| `title` | string | — | 视频名称，≤255；留空回退到链接末段文件名 |
| `cover_url` | string | — | 远程封面图；留空则自动抽关键帧 |
| `category_id` | int | — | 目标分类；`0` 表示用 `default_category_id` |
| `description` | string | — | 简介，≤2000 |
| `sort` | int | — | 排序值，越大越靠前 |
| `headers` | object | — | 附加请求头，如 `{"Referer": "...", "Cookie": "..."}` |
| `force` | bool | — | 同一链接已成功下载过时是否重下 |

`headers` 也接受 `"Key: Value"` 的多行文本（页面表单走这条路径），
服务端统一归一化成字典。

**响应** `data` 为任务快照（见 §5.3），`stage=queued`，下载在后台线程进行。

### 5.3 查询与维护

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/download/tasks` | 任务列表 + 统计（`total`、`stats.by_stage`） |
| GET | `/api/admin/download/tasks/{task_id}` | 单任务快照 |
| POST | `/api/admin/download/tasks/{task_id}/cancel` | 取消（结束进程树 + 清暂存目录） |
| POST | `/api/admin/download/tasks/{task_id}/retry` | 重试（失败/取消态可用） |
| DELETE | `/api/admin/download/tasks/{task_id}` | 删除记录（**不动已入库的视频**） |
| POST | `/api/admin/download/tasks/cleanup` | 清理 7 天前的失败/取消任务 |

快照字段（节选）：

```json
{
  "task_id": "5f3c1a...",
  "source": "api",
  "url": "https://example.com/hls/index.m3u8",
  "title": "示例影片",
  "category_id": 1,
  "cover_preview": "/media/covers/2026/09/x.jpg",
  "stage": "downloading",
  "stage_text": "下载中",
  "percent": 42.15,
  "total_bytes_text": "812.40 MB",
  "done_bytes_text": "342.42 MB",
  "speed_text": "8.21 MB/s",
  "eta_text": "00:57",
  "video_id": 0,
  "message": "下载中 23/46 片",
  "error": "",
  "log_tail": "……",
  "elapsed": 41.7
}
```

`video_id` 在 `stage=finished` 时才有值；`error` / `log_tail` 是排障用的原始输出尾部。

## 6. 任务阶段与进度模型

`percent` 是**整体**进度，按阶段区间映射，不会中途回退：

| stage | 区间 | 含义 |
| --- | --- | --- |
| `queued` | 0 | 已入队，等待并发槽位 |
| `downloading` | 0 → 80 | 分片下载，`message` 形如 `下载中 12/46 片` |
| `muxing` | 80 → 88 | ffmpeg 混流封装（音视频分离的流才走这段） |
| `ingesting` | 88 → 90 | 落盘、算摘要 |
| `probing` | 90 → 95 | 探测时长/分辨率 |
| `covering` | 95 → 100 | 抽帧或下载远程封面 |
| `finished` | 100 | 完成，`video_id` 有效 |
| `failed` | — | `error` 给出原因，`log_tail` 保留下载器原始输出 |
| `cancelled` | — | 用户主动取消 |

**多轨下载的进度怪相**：HLS 常见 video / audio 两条播放列表，`N_m3u8DL-RE` 是**串行**下载
再混流，且会打印 `0/100` 的占位轨。因此解析时按 `Vid` / `Aud` / `Sub` 切块、
各取最后百分比后**取最大值**——取最小值会让进度长期卡在 0%，
只有 `max` 才能保证「视频下完了、音频还在下」时进度停在 80% 等着进混流。

另外两个坑（已在实现里处理，改动时别踩回去）：

- 输出重定向到管道时，进度条**整段没有换行**，必须按 `\r` / `\n` 一起切；
- `100.00%Vid` 之间没有分隔符，`\b(Vid|Aud)\b` 匹配不到，得用 `(Vid|Aud|Sub)(?![A-Za-z])`。

双看门狗：30 秒无输出则改用**暂存目录实际体积**估算进度；超过 `timeout_seconds` 强杀。

## 7. 处理流程

```
建任务 → download_task(stage=queued)
  ↓ 线程池拿并发槽位
N_m3u8DL-RE --save-dir storage/tmp/m3u8/<task_id>
              --save-name <任务名> --tmp-dir <task_id>/_tmp
              --auto-select -M format=mp4 --ffmpeg-binary-path ...
  ↓ 进程结束，校验退出码与取消标记
挑产物  → 排除 _tmp / json / log，按媒体扩展名取体积最大的一个
  ↓ 文件改名（存量名 + 产物真实后缀）→ 移入 storage/videos/YYYY/MM/
算 SHA-256（record_hash 开启时）
拉封面  → 远程下载（校验魔数判格式、体积上限）→ storage/covers/…
  ↓ 这几步之前都失败过就整体失败
ingest_file() → 容器校验/自动转封装 → probe → 封面兜底 → 写 video 表
  ↓
mark_finished(video_id) + 写 upload_session 台账（供秒传）
  ↓
清理暂存目录（先归还并发槽位，再删目录）
```

几个刻意的设计：

- **原文件名用产物的真实后缀**。链接是 `xxx.m3u8`，直接拿它当入库文件名会让落盘文件
  变成 `xxx.m3u8`，而内容其实是 mp4 —— 后续容器校验会误判。
- **暂存目录独立于产物目录**：`_tmp` 和 `download.m3u8` 这类中间文件都在
  `storage/tmp/m3u8/<task_id>/` 下，挑产物时排除，不会混进 `storage/videos`。
- **摘要读的是落盘后的 mp4**：与批量导入（读源文件）不同，但目的相同 —— 让网页端
  再上传同一文件时命中秒传。
- **清理失败只记日志**：删暂存目录失败不影响任务判定为成功，
  避免「视频已入库但状态是失败」这种更糟的结果。

## 8. 数据表

`download_task`（`sql/update.sql` 变更 #1，幂等 `CREATE TABLE IF NOT EXISTS`）：

关键字段：`task_id`(PK) / `user_id` / `source`(`admin`\|`api`) / `url` / `headers` / `title` /
`cover_url` / `category_id` / `description` / `sort` / `stage` / `percent` / `total_bytes` /
`done_bytes` / `speed` / `eta` / `staging_dir` / `file_path` / `cover` / `video_id` /
`message` / `error` / `log_tail` / `elapsed` / 四个时间戳。

索引：`idx_stage`、`idx_user`、`idx_created`。

服务启动时（lifespan）会把**上次进程遗留的活跃任务**（`queued`/`downloading`/`muxing`/
`ingesting`）统一标记为失败并注明「服务重启中断」，避免页面上挂着永远不动的进度条。

## 9. 与批量导入工具的分工

| | m3u8 下载 | 批量导入（doc 10） |
| --- | --- | --- |
| 输入 | 链接 | 服务器磁盘上的文件 |
| 走 HTTP 接口 | ✅（可给插件调用） | ❌（本机 CLI） |
| 鉴权 | JWT 或 `X-API-Token` | 无（谁能登服务器谁就能导） |
| 需要外网 | ✅ 必须 | ❌ |
| 并发 | 后台线程 + 信号量 | `--jobs` |
| 判重摘要 | 读落盘后的 mp4 | 读源文件 |

两者都写 `upload_session` 台账，所以**互相之间也能判重命中**。

## 10. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| `code=5011` 工具未就绪 | 跑 `python scripts/fetch_tools.py`；或检查 `download.binary` 路径 |
| `code=5010` 功能已关闭 | `download.enabled: false`，改回 `true` 并**重启服务** |
| `code=5013` 任务正在运行 | 该任务已在跑或已结束，取消/重试/删除只对特定状态生效 |
| 进度长期 0% | 检查回来的流是不是「占位轨 + 真实轨」结构；看任务卡片的 `log_tail` |
| 下载下来没声音 | 缺 ffmpeg → 音视频分离的流没被混流。装 ffmpeg 后重试 |
| 一直卡在 `downloading` | 源站限速或链接失效，看 `log_tail`；等 `timeout_seconds` 强杀或手动取消 |
| 插件报 401 | 令牌为空、不匹配，或请求头名写错（要 `X-API-Token`，不是 `Authorization`） |
| 页面显示「工具未就绪」但命令行能跑 | 服务进程的**工作目录**不对，`binary` 相对路径解析失败，改用绝对路径 |

> 改完 `config.yaml` 必须**重启后端进程**才生效（`dev.reload: false`）。
> 前端静态资源改完刷新即可。

## 11. 安全注意

- `api_token` **不要提交进仓库**，用 `MM_DOWNLOAD_API_TOKEN` 环境变量注入；
- 令牌是长期有效的静态凭据，建议只用在自己的内网/本机插件上，暴露到公网前先想清楚；
- 令牌调用会把任务归属到 `api_user_id`（默认第一个管理员），
  所以 /admin 的任务列表里会出现这些任务，这是预期行为；
- `headers` 里的 `Cookie` 会写进 `download_task.headers` 字段，注意别把敏感凭据留在库里。
