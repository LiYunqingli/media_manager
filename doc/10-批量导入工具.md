# 批量导入工具（服务端 CLI）

`scripts/import_videos.py` 用于把**已经在服务器磁盘上**的视频批量登记进系统，
跳过分片上传的三步（切分片 → 逐片传输 → 拼接），其余处理保持一致。

## 1. 什么时候用它

| 场景 | 用哪个 |
| --- | --- |
| 运维/管理员在服务器上，文件已就位（移动硬盘拷入、`rsync` 同步、爬虫落盘） | **本工具** |
| 普通管理员在浏览器里传本地文件 | 管理端分片上传（[05](./05-分片上传设计.md)） |
| 上传中断需要续传、需要实时进度条 | 管理端分片上传 |

区别只在前三步：本工具用**文件系统本地搬运**替代"切分片 + HTTP 传输 + 拼接"，
因此速度快得多（同盘移动 100MB 文件 0.1s 级，硬链接更是零拷贝）。

**入库后的结果两条链路完全一致**——因为都走 `app/services/ingest_service.py`:

```
容器校验/自动转封装 → 元信息探测 → 抽帧封面 → 写入 video 表
```

`ingest_service.ingest_file()` 是唯一实现，分片上传的 `_merge_worker()` 也调用它。
这样不会出现「网页上传的文件会自动转封装、CLI 导入的不会」这类行为漂移。

## 2. 快速上手

```bash
# ① 先干跑：只列文件、标出容器不符的风险项，不落盘不写库
python scripts/import_videos.py D:/待导入 --category-name 电影 --dry-run

# ② 正式导入（默认：复制进库、保留源文件、递归不开启）
python scripts/import_videos.py D:/待导入 --category-name 电影

# ③ 目录树按子目录自动建分类，并移动源文件
python scripts/import_videos.py D:/剧集 --category-from-subdir -r --mode move

# ④ 只导入一个文件（参数既可以是目录，也可以是文件；不需要 -r）
python scripts/import_videos.py E:/珠江.mp4 --category-id 10
```

`--dry-run` 的输出会顺带嗅探真实容器：

```
[1/2]   17.93 MB  剧集    mpegts   伪装成MP4的TS.mp4  ⚠️ 实为 MPEGTS 容器，导入时将自动转封装
[2/2]    5.18 KB  电影    mp4      小测试片.mp4
```

## 3. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `路径...` | 必填 | 待导入的**目录或单个视频文件**，可给多个；传文件时不受 `-r` 影响（直接采纳），后缀仍按允许列表校验 |
| `-r, --recursive` | 关 | 递归子目录 |
| `--category-id N` | — | 目标分类 ID |
| `--category-name NAME` | — | 目标分类名，不存在则自动创建 |
| `--category-from-subdir` | 关 | 按「一级子目录名」建分类；直属于根的文件落回上面两个参数指定的分类 |
| `--mode {copy,move,link}` | `copy` | 源文件处理方式，见 §5 |
| `--sort N` | `0` | 入库排序值，越大越靠前 |
| `--ext .mp4 .mkv` | 取 `config` | 覆盖允许的扩展名 |
| `--limit N` | 0 | 最多处理 N 个（0=不限），试点用 |
| `--include-hidden` | 关 | 包含 `.` 开头的文件（默认跳过 macOS 的 `._xxx` 元数据文件） |
| `--force` | 关 | 命中判重也重新导入 |
| `--dry-run` | 关 | 只列文件，不落盘不写库 |
| `--jobs N` | 1 | 并发数（上限 8）。抽帧受全局锁保护，建议不超过 4 |
| `--title-from {stem,filename}` | `stem` | 标题取文件主名还是全名 |
| `--description TEXT` | 空 | 统一写入的简介 |
| `--no-hash` | （默认算） | 跳过 SHA-256 计算，见 §4 |
| `--user-id N` | 首个管理员 | 导入台账归属用户 |
| `-v, --verbose` | 关 | 打印后端 DEBUG 日志 |
| `--json` | 关 | 结果以 JSON 输出，便于脚本消费 |

## 4. 判重与秒传（默认算 SHA-256，为什么）

导入前对源文件计算一次 SHA-256，用它做两件事：

1. **判重**：命中 `upload_session.file_hash` 已完成的记录即跳过；
2. **秒传**：写一条 `stage='finished'` 的台账记录，网页端再上传同一文件时
   `init_upload` 直接返回 `instant=true`（秒传逻辑完全依赖 `upload_session.file_hash`）。

之所以不省这一步：**容器不符的文件入库时会被自动转封装，落盘体积与源文件不再相等**
（实测 18.8MB 的 TS → 17.4MB 的 MP4），只靠「同名 + 同大小」判重会失效，
同一批文件会被反复导入。摘要读的是**源文件**，不受转封装影响。

代价是每个文件多读一遍（本地盘 100MB 约 0.2s）。不在意判重精度、只想快速灌数据时：

```bash
python scripts/import_videos.py D:/待导入 --category-id 10 --no-hash
```

此时判重退化为「原始文件名 + 字节数」，并且**不会**建立秒传台账。

## 5. 搬运方式

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| `copy`（默认） | 复制进 `storage/videos/YYYY/MM/`，源文件保留 | 最安全，源目录留档 |
| `move` | **先复制、入库成功后才删源**，源目录导入后清空 | 硬盘腾挪、整理归档 |
| `link` | 同盘硬链接（零拷贝），跨盘/不支持时自动退回复制 | 大文件、同盘、只读源 |

`move` 之所以先复制再删，是为了避免「文件已移走但入库失败」这种最难收拾的状态：
只要入库没成功（探测异常、DB 写入失败），源文件原地不动。

## 6. 分类策略

正式导入**必须**指定分类，三种方式任选其一：`--category-id` / `--category-name` /
`--category-from-subdir`。一个都不给会在开跑前直接报错退出（code 2），
**不会**逐个文件失败一遍（`--dry-run` 例外，它不写库，只提示）。

- 固定分类：`--category-name 电影`（不存在自动创建）或 `--category-id 10`；
- 按目录结构分：`--category-from-subdir` 取**相对搜索根的第一级目录名**作为分类名，
  不存在自动创建，同名并发创建有锁保护 + 缓存，不会建出重复分类。

```bash
D:/剧集/
  ├─ 第一季/xx.mp4     -> 分类「第一季」
  ├─ 第二季/yy.mp4     -> 分类「第二季」
  └─ 花絮.mp4          -> 回落到 --category-id/--category-name 指定的分类
```

用了 `--category-from-subdir` 时，若根目录下也有文件，**必须**同时给
`--category-id` 或 `--category-name` 作为默认分类，否则工具会直接报错退出（code 2）。

只导入**单个文件**时别用 `--category-from-subdir` —— 单个文件没有「子目录」可言，
它会落到 `--category-id` / `--category-name` 指定的分类。

## 7. 常见用法

```bash
# 只导入一个文件
python scripts/import_videos.py E:/珠江.mp4 --category-id 10

# 只导入 mp4/mkv，先试 5 个看效果
python scripts/import_videos.py D:/待导入 -r --ext .mp4 .mkv --category-id 10 --limit 5

# 大目录快速灌数据（不算摘要、4 并发）
python scripts/import_videos.py D:/待导入 -r --category-id 10 --no-hash --jobs 4

# 交给定时任务，结果存 JSON 供后续统计
python scripts/import_videos.py /data/inbox --category-id 10 --json > /var/log/import.json

# 强制把同一批文件重新导入一遍（会生成新的存储文件）
python scripts/import_videos.py D:/待导入 --category-id 10 --force
```

### 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部成功或跳过 |
| 1 | 存在失败项（清单在末尾打印；`--json` 时在 `items[].status == "failed"`） |
| 2 | 参数或环境错误（路径不存在、扩展名不在允许列表、分类缺失、未指定默认分类） |

`--json` 的 `items[].status` 取值为 `imported` / `skipped` / `failed`，
单文件失败不会中断整批。

## 8. 注意事项

- **必须在服务器本机运行**：工具直接读写 `storage/` 与数据库，不走 HTTP 接口，
  因此不受 `app.host/port` 影响。运行期间服务可以在跑（用不同的 DB 连接），
  导入完成后管理端刷新即可看到新视频。
- **运行前最好核对配置**：脚本启动时会打印生效的 `storage` 路径、数据库与配置文件，
  避免误连生产库。
- **属于「服务端工具」，不是接口**：不经过鉴权，谁能登服务器谁就能导入。
  `--user-id` 只用于台账归属，不做权限校验。
- **台账会出现在管理端「最近上传会话」**：这是秒传功能的前提，不是冗余数据；
  不想写台账就用 `--no-hash`。
- 源文件已在 `storage` 内时（例如手工放进 `storage/videos/` 的文件），工具**不搬运**，
  直接引用现有路径登记入库。
- 探测失败（时长/分辨率记为 0）不会阻断入库，会在结果里提示；
  之后可在管理端对视频执行「重新探测」补救。
